# Goule 验证手册

## 本地检查

运行 `./scripts/check`。需要 Bash、Git、Python 3、JDK 17 和 Android SDK。将 `JAVA_HOME` 指向 JDK 17，将 `ANDROID_HOME` 指向 SDK，或在本地 `local.properties` 配置 `sdk.dir`。使用 Android Studio 的 SDK Manager 或 `sdkmanager` 安装 `platforms;android-35`、`build-tools;35.0.0`。真机安装另需 `platform-tools`。首次构建需要下载 Gradle 和 Maven 依赖。

仓库检查涵盖 Git 改动中的空白错误和 Markdown 行内相对链接。Gradle Wrapper 固定为 8.11.1，运行 `check assembleDebug`，执行 Lint、JVM 单元测试并构建调试 APK。计时测试覆盖分段累计、重复事件、冷冻中离开和返回、到期后开启下一轮。设备拦截行为由下面的真机流程验证。

## 能力原型真机验收

在 Pixel 或接近原生的设备以及至少一款国产 ROM 上执行。设备需运行 Android 11 或以上，并安装至少一个普通第三方 App。用 `adb install -r app/build/outputs/apk/debug/app-debug.apk` 安装 Goule。若系统阻止侧载 App 开启无障碍，按系统提示查看该 App 的受限设置。

1. 在 Goule 中选择一个调试目标。先点「稍后」，确认仍可配置目标且限制未启用。再次打开说明，点「同意并前往设置」，从系统设置启用服务。回到 Goule 确认服务已连接。
2. 打开目标约 4 秒，切到其他 App 至少 10 秒，再返回目标。确认目标只剩约 6 秒额度。另起一轮，锁屏后等待至少 10 秒，再解锁并切出、重新进入目标，确认锁屏期间没有累计用量。原型以新窗口事件确认解锁后的前台，直接解锁回到目标的表现也单独记录。
3. 用完额度，确认遮罩出现且触摸无法传到目标 App。点「返回桌面」，在 20 秒冷冻到期前重新打开目标，确认仍拦截。保持目标在前台，确认到期时遮罩撤下，且新的 10 秒额度用完后可再次冷冻。
4. 冷冻期间检查其他 App、系统导航、系统设置、来电与紧急入口的可用性。再进入系统设置关闭服务，确认回到目标后可正常交互。
5. 记录提交 SHA、机型、Android 和 ROM 版本、安装来源、各步骤结果、观测延迟及异常复现步骤。未执行的项目标记为待验证。

原型仅对选定的单个普通第三方 App 生效。额度和冷冻状态留在无障碍服务内存，服务重连、进程重启或更换目标后重新计时。前台状态依赖窗口事件，输入法、系统弹窗和厂商系统的事件差异属于本阶段验证范围。

## 模拟器记录

2026-11-10，Pixel 6 AVD，Android 15 AOSP x86_64（API 35，AE3A.240806.019）。通过 ADB 安装调试 APK 和记录触摸的测试 App。应用内同意后打开系统设置，测试通过 ADB 切换服务开关，并确认 Goule 显示服务已连接。

- 切出至桌面等待 10 秒、息屏等待 11 秒均暂停累计。该轮回到目标后约 2.4 秒出现遮罩。
- 遮罩拦截目标区域的点击。「返回桌面」可离开目标，冷冻期间重新打开目标会再次拦截。到期后目标恢复接收点击，下一轮用完后可再次冷冻。
- 冷冻期间打开系统设置时遮罩撤下。返回目标后遮罩恢复，关闭服务时撤下。
