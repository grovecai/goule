# Goule 实施计划

产品和技术决策以 [Android 首版设计](android-design.md) 为准。更新阶段状态时，附上检查结果或真机记录的位置。

## 当前任务：Android 能力原型

- [x] 建立最小 Android 工程，提交 Gradle Wrapper，记录 JDK 和 Android SDK 版本，让 `./scripts/check` 执行本地构建检查。
- [x] 实现单个调试目标的能力验证。用户同意并从系统设置启用服务后，观察进入目标 App、离开和锁屏，使用短额度触发遮罩。
- [ ] 按 [验证手册](verification.md) 在 Pixel 或接近原生的设备与至少一款国产 ROM 上验证前台事件、遮罩、桌面返回和系统入口。记录设备差异，明确原型能覆盖的场景。

本轮仅实现一个本地选定的普通 App。调试额度为 10 秒，冷冻为 20 秒。保留分段累计、离开和锁屏暂停、冷冻截止和返回桌面。计时状态留在服务内存，目标包名与授权说明确认保存在本机。验收分为构建、计时自动化和真机验证。

通过能力验证后，再接入独立规则引擎与持久化，并完成规则配置、首次使用和服务异常恢复链路。各阶段的通过条件见 [设计稿的验证顺序](android-design.md#4-验证顺序)。

## 当前状态

最小工程和单目标原型已实现。`./scripts/check` 通过，覆盖仓库检查、Lint、三项 JVM 计时测试和调试 APK 构建。Android 15 模拟器通过单目标拦截流程，见 [模拟器记录](verification.md#模拟器记录)。Pixel 和国产 ROM 的 [真机验收](verification.md#真机记录) 待执行。
