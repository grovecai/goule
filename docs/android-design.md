# 「斩心魔」Android 首版设计

「斩心魔」是面向个人的 Android 自律工具，帮助用户中断一次无意识刷屏。以 Enough 的 iOS 交互为基线，采用「每个 App 独立固定周期 → 周期内累计用量 → 用满后禁用至周期结束 → 到点一次重置」。拦截能力、计时精度和设备兼容性的实际覆盖见 [验证手册](verification.md)。

## 1. 产品行为

- **逐 App 设置**。每条规则包含可刷时长和休息时长（旧字段名为禁用时长），新建默认「5 分钟 / 115 分钟」，即每 120 分钟重置一次 5 分钟额度。已有戒律保留原配置，最早单目标原型数据迁移仍采用其原有 20/30 分钟。首版建议先沿用 iOS 的可用 1–180 分钟和禁用 15–180 分钟，便于跨端一致。Android 的候选实现按截止时间判断，15 分钟是产品选择，短禁用可用调试配置验证。iOS 的 19 条调度上限无需直接搬过来，Android 首版容量以性能实测为准。
- **累计可交互前台时间**。同一 App 分段使用会相加。切出、锁屏和禁用期间停止累积。首版支持当前 Android 用户的普通全屏 App，后台播放、分屏、画中画和工作资料另行验证。
- **固定周期与独立禁用**。规则「刷 U 分钟 / 歇 B 分钟」表示每 U+B 分钟重置一次 U 分钟额度，各 App 从首次实际使用起独立起算。周期内分段累计，用满后禁用到本周期结束；未用满也在同一边界重置，剩余不结转，不逐秒恢复。连续刷 10/歇 120，周期为 130 分钟；刷 20/歇 30，周期为 50 分钟。长期闲置时跳过已结束周期并保持原相位，打开页面或重新进入目标不会改变周期起点。固定周期允许在前一周期尾和下一周期头连续使用两份额度，这是本次确认后的行为，不再承诺任意连续窗口的累计上限。
- **编辑与移除**。首次使用固定当前周期的可刷额度和长度。修改任一时长保留当前周期起点、已用量、原额度和结束时间，下一周期起采用最新配置；即使当前周期还未使用，也不移动已建立的周期。尚未开始首个周期则立即采用最新配置。两次实际修改至少间隔 5 分钟。创建满 1 小时，且最近一次真正开始禁用（如有）满 1 小时后可确认移除，完成后明确解除该规则限制；重新选择目标仍开始该新 App 的独立周期，沿用移除保护时间。删除后重加不属于仍在执行的原规则，防删除/卸载不属于本次计时修复范围。
- **设备控制权**。个人版保留系统卸载与关闭服务的入口。设置页可以提供规则保护说明，防卸载不承诺跨品牌支持。受管设备的包挂起或防卸载属于独立产品形态。 [Android 设备策略接口](https://developer.android.com/reference/android/app/admin/DevicePolicyManager.html)

## 3. 技术方案

首版沿用现有 Kotlin、原生 Android View 和单进程 `AccessibilityService`。规则量小，单进程使用一份本地规则快照，减少对框架与数据库迁移的依赖。最低支持 Android 11（API 30），发布时按实际渠道要求确定目标 SDK 和支持设备。

| 组件 | 责任 |
| --- | --- |
| App 列表 | 用 `PackageManager` 查询 `MAIN / LAUNCHER` Activity。通过 manifest 的 `<queries>` 声明所需范围，按包名去重，排除「斩心魔」自身、桌面、设置、来电和紧急等系统入口。 [包可见性](https://developer.android.com/training/package-visibility/declaring) |
| 规则引擎 | 独立于 Android 界面的纯 Kotlin 状态转换。输入为前台切换、锁屏/唤醒、到期、编辑和权限状态；输出为累计更新及拦截决策。 |
| 前台识别 | 验证 `TYPE_WINDOW_STATE_CHANGED` 是否足以区分目标 App、离开和系统窗口。监听包名、时间和启动器窗格出现或消失信号。目标从最近任务恢复时，合并启动器的短促收尾事件，避免撤下已经恢复的禁用遮罩。其他包只用于判断是否离开，随即丢弃。关闭窗口内容读取，不遍历节点、不读取输入、不截图。 [事件与能力配置](https://developer.android.com/reference/android/accessibilityservice/AccessibilityServiceInfo) |
| 拦截 | 服务确认当前目标 App 正处于禁用时，附着可触摸的 `TYPE_ACCESSIBILITY_OVERLAY`。切换到其他应用、服务断开或到期时撤下。「返回桌面」请求 `GLOBAL_ACTION_HOME`。「关闭 App」打开系统最近任务，由用户上滑移除目标卡片。操作失败时保留有效遮罩并允许系统导航。 |
| 存储与时间 | 按包名保存规则、当前周期起点与累计量、可刷额度和周期快照、最近禁用开始、已计时水位、创建时间和上次成功修改时间。重报或重叠的观察区间不重复累计。滚动版区间合并为已保存累计量；早期累计版直接保留用量。旧起点加周期仍在最后保存时间之后时沿用该起点，否则以最后保存时间开启一个保留已用量的固定周期，避免切换模型直接清零；尚有效的旧禁用截止保留为下限。无法恢复旧版本已清空或未提交的用量。配置与禁用切换立即提交，前台使用进度约每 5 秒保存并在离开时提交。规则时钟同一次开机依赖 `elapsedRealtime`，跨开机按系统时间恢复，并以最近保存的规则时间为下限。 |

### 计时和恢复

系统音量面板不会替换底层前台 App。仅对已确认的 SystemUI 弹窗类保留当前目标并重新核对交互状态和禁用到期；OPPO/ColorOS 的 `OplusVolumeDialogView$CustomDialog` 虽上报 `fullScreen=true`，仍属于透明音量面板。普通非全屏 `android.app.Dialog` 同样保留底层目标。未知系统窗口、通知栏、设置和其他 App 继续按离开处理，锁屏及断连仍清空前台，不因迟来的弹窗关闭事件恢复旧目标。不读取事件文字或窗口内容，不拦截音量键。

1. 从已确认的前台事件开启会话，短周期检查交互状态和锁屏。仅累计短间隔的 `uptimeMillis` 增量，并用 `elapsedRealtime` 排除跨休眠采样。屏幕状态变化时丢弃尚未确认的区间，等新的窗口事件再继续。
2. 达到当前周期额度时，用一次事务保存累计量和禁用开始，再展示遮罩。截止为当前周期结束时间，不通过重复打开重新开始。跨周期采样按边界拆分；不补算已被遮罩覆盖的区间。
3. 遮罩可见时安排到期移除；进程休眠、重启或从桌面重新打开目标 App 时，先推进到当前固定周期，再按累计量和升级保留的截止判断是否恢复。只恢复已提交的会话增量，不补算未观察到的活跃时间。同次开机的系统时间调整只影响展示时间。重连和重启后读取已保存的规则时钟。服务未连接或前台归属不明确时，清除不可靠的遮罩并展示可确认的服务状态。
4. 若真机发现前台事件漏报或重连后难以确认活动 App，再验证 `UsageStatsManager.queryEvents` 作为补偿。该方案需要额外的「使用情况访问权限」，要说明用途并防止和实时会话重复计时。首轮原型只请求无障碍服务。 [UsageStatsManager](https://developer.android.com/reference/android/app/usage/UsageStatsManager)

### 发布边界

Google Play 版本应准确披露无障碍用途，提供单独的应用内显著披露、明确同意、Play Console 声明与演示。「斩心魔」的主要用途是个人自律，服务不声明 `isAccessibilityTool=true`。覆盖范围限于用户设置规则的前台 App；设备设置和卸载流程保持可用。声明能否获批由渠道审核决定。 [Google Play AccessibilityService 政策](https://support.google.com/googleplay/android-developer/answer/10964491)

## 4. 验证顺序

| 阶段 | 通过条件 |
| --- | --- |
| 能力原型 | 在 Pixel 或接近原生的设备，以及至少一款国产 ROM 上，授权后能识别普通 App 进入、离开、锁屏。用满后遮罩可阻止触摸，「返回桌面」正常，再打开仍拦截。验证系统设置、来电和紧急入口可以访问。 |
| 规则引擎 | 自动化覆盖分段累计、两个 App 禁用独立、固定周期重置与闲置相位、重复与重叠回调、编辑保留当前周期、进程重启恢复、设备时钟变化。 |
| 用户链路 | 真机跑首次拒绝和恢复、App 选择、A 用满后 B 可用、锁屏跨过 A 截止后 A 解锁且 B 仍禁用、A 周期结束后按新额度计时。记录机型、Android/ROM 版本、安装渠道与观测延迟。 |
| 兼容和发布 | 验证服务被杀、从通知进入、最近任务、键盘和系统弹窗等切换路径，明确分屏与画中画边界；若目标为 Google Play，完成无障碍声明和审核验证。 |

优先做能力原型。只有确认前台事件和遮罩能稳定覆盖核心路径，再把完整规则界面和更多机型支持接上。

### 后台运行适配

无障碍服务由系统绑定，显式设置 `stopWithTask=false`，任务移除回调保存已有进度，保持服务会话。重连沿用已提交的规则时钟，等待新前台事件。后台设置使用公开 Android 应用信息和电池优化入口，启动失败逐级回退。厂商差异集中在 `BackgroundSupport.kt` 的配置入口，当前接入 OPPO 指引，其他设备使用通用指引。电池优化豁免不等同于服务连接或厂商后台权限已开启。

后台设置仅为可选稳定性指引，不读取或展示完成状态，不保存用户确认，不参与首次继续、添加心魔与戒律缺项门禁。无障碍服务连接仍为必要条件。旧后台确认记录不再使用。此约定覆盖此前后台必配和自动/手动完成判定。

耗电管理的具体选项由厂商提供；OPPO 指引使用实测的「应用信息 → 耗电管理 → 完全允许后台行为」，其他厂商走通用说明，可在 BackgroundProfile 扩展。电池优化是 Android 通用机制，使用公开列表入口，各系统界面名称和整合方式可能不同。参考 [Android PowerManager](https://developer.android.com/reference/android/os/PowerManager)。

### 系统撤销无障碍授权的边界

OPPO PLJ110 / ColorOS 16.1.0 的重启对照日志确认，系统会因 `sideload_app` 主动关闭本应用的无障碍服务，发生在应用进程已启动之后。耗电允许与无障碍授权分别处理。应用不尝试自行重开安全设置或把启动进程当作授权恢复；已激活但开关关闭时显示暂停与重新开启指引，绑定恢复后继续使用原规则。厂商恢复说明集中在 BackgroundSupport，其他系统保留通用提示。

清理后组件仍在启用名单但未实际连接时，先显示「正在连接」，持续 5 秒仍未连接则显示「连接中断」，指导用户在系统中先关闭再开启服务。全局 ACCESSIBILITY_ENABLED 反映当前运行情况，不能独自用于判断本组件授权是否已关闭。恢复成功只认服务实际连接，保留已提交用量及禁用截止；后台允许与最近任务锁定仅用于减少中断，不承诺规避所有系统清理。
